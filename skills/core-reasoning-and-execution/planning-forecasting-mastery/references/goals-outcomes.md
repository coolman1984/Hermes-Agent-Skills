# Goals and Outcome Definition

Plan from outcome, not activity. A goal describes the state or decision we want; a task is work done along the way. Use measurable success criteria, definition of done, and explicit non-goals.

Frameworks: SMART, OKRs, North Star metric, working backwards. Use them lightly; they can over-engineer small tasks.

Worked example: “Automate Excel reports” becomes “trusted monthly report generated from source files with row-level provenance and validation warnings.”

Invoke this when: a goal sounds like activity. Misleads when: metrics become vanity numbers.

Sources/leads: PMI PMBOK requirements/scope, OKR practice, Amazon working-backwards narrative.
