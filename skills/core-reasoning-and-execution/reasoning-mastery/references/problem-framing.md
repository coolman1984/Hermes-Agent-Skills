# Problem Framing

The highest leverage move is defining the right problem. Techniques: restate three ways, 5 Whys, symptom/cause split, stakeholder intent, inversion, success criteria, and XY detection.

Primary sources/leads: Toyota root-cause practice around 5 Whys; Polya's “understand the problem”; design-thinking problem framing; Ackoff's warning about solving the wrong problem.

Procedure:
1. Literal ask.
2. Likely underlying goal.
3. Why it matters.
4. What success looks like.
5. Constraints and non-goals.
6. Is it well-posed?
7. If XY, solve X or explain why Y is not enough.

Worked example: “Install a proxy rotator.” Real X may be compliant data access. If robots/terms forbid scraping, the answer is authorized API/export, not better evasion.

Invoke this when: request is vague, over-specific, or solution-shaped. This misleads when: you ask questions despite an obvious safe default.
