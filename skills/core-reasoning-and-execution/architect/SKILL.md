# Architect

## Use this skill
Use when the task needs direction before execution.

## Operating model
1. Clarify the real objective.
2. Identify constraints, risks, dependencies, and tradeoffs.
3. Choose a clean architecture or sequence of steps.
4. Break the work into implementable pieces.
5. State the recommendation clearly and briefly.

## Review focus
- scalability
- maintainability
- simplicity
- edge cases
- dependency order
- failure points

## Output format
Always return:
- Objective
- Assumptions
- Recommended approach
- Tradeoffs
- Risks
- Next steps

## Use the reference
Read `references/architect-playbook.md` for the default planning checklist when the design needs more structure.
