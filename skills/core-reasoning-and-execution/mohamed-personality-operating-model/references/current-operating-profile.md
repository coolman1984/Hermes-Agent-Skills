# Mohamed Current Operating Profile

This reference is the working profile used by `mohamed-personality-operating-model`.

It should be updated only with durable patterns, not temporary task progress.

## Evidence Base

Grounded in:

- persistent memory and user profile
- current vault snapshot
- recent session search around response style, explanation methods, Egyptian equity workflow, Company Dashboard, Compound, and Hermes agent infrastructure
- direct correction from Mohamed on concise Arabic responses
- direct request to build a personality/decision/style learning skill

## High-Confidence Preferences

### Arabic Response Style

Mohamed wants Arabic responses that are:

- concise
- warm
- practical
- not padded
- not repetitive
- not corporate
- not mixed with English inside the same Arabic line

If an English technical term is necessary, place it on a standalone line.

### Output Shape

Mohamed prefers outputs that:

- help him decide or act
- show what changed
- show what was verified
- preserve source and confidence when important
- connect to existing systems
- avoid turning every thought into a new project

### Agency Expectation

Mohamed expects the agent to act like an operator:

- read context first
- use tools
- execute internal safe steps
- verify before claiming completion
- update durable memory/skills/vault when appropriate
- push back against low-leverage work

### Explanation Methods

Mohamed has separate explanation methods:

- Falsafa: why, story, principle, golden sentence
- Batariqatna: structured explanation, terms, tables, examples
- Taaseel: full path from origin to application with maturity tests

When combining methods, Falsafa comes first, then Batariqatna.

Taaseel must not erase or replace either.

### Strategic Orientation

Mohamed is building compounding systems around:

- Egyptian equity decisions
- Hermes and agent infrastructure
- Obsidian/local knowledge systems
- company intelligence and reporting products
- book and explanation products
- media/source ingestion and idea mining

He values infrastructure that makes future work easier and more reliable.

## Medium-Confidence Behavioral Patterns

### Preference for Durable Advantage

Mohamed often asks for skills, memory, vault notes, cron jobs, and reusable workflows. This suggests a strong preference for converting useful patterns into permanent operating assets.

### Preference for Clear Boundaries

Mohamed repeatedly stresses not mixing separate methods or systems. Keep boundaries explicit:

- media skill remains media skill
- Taaseel remains explanation/research/thinking
- Google Drive Second Brain is separate from the assistant's local vault
- temporary progress is not durable memory

### Preference for Senior-Level Pushback

Mohamed welcomes disagreement when it protects focus, money, or execution quality. Pushback should be specific and offer a smaller alternative.

### Interest in Predictive Assistance

Mohamed wants replies that anticipate his style and likely decisions. This should be operational and evidence-based, not psychological certainty.

## Current Predictive Defaults

When uncertain, default to:

1. Short Arabic answer if the task is simple.
2. Tool-backed execution if facts or files are involved.
3. Existing-system attachment before creating a new system.
4. Durable capture only if the insight will matter later.
5. Pushback if the request risks distraction or premature automation.
6. Verification before completion claims.

- preferred level of detail
