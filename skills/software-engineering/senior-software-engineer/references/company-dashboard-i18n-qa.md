# Company-Dashboard i18n QA — Session 2026-06-15

## Problem

8+ English text strings visible across all 6 Arabic dashboard tabs despite the
existing i18n system. Zero console errors — the issue was purely translation
gaps, not JavaScript failures.

## Root causes (categorized)

### 1. Case-sensitivity mismatches
Dictionary had `"ACTUAL 2026 P01-P05"` but `tr()` was called with
`"Actual 2026 P01-P05"` (mixed case). Same for `"CHANGE VS FY2025"` vs
`"Change vs FY2025"`.

### 2. Dynamic strings needing regex, not dictionary
Signal copy texts in the CFO Decision Center were built at runtime with
variables (`periodLabel`, `priorLabel`):
```
periodLabel + ' margin versus ' + priorLabel + '. Protect the mix and cost gains…'
```
Dictionary lookup can't match these; they need regex patterns in `translateText()`.

### 3. Hardcoded English in app.js table headers
Lines 735 and 1327 built `<th>` elements with raw English strings instead of
wrapping with `tr()`:
```js
// BEFORE
'<th>Change vs FY' + cov.priorYear + '</th><th>Change %</th>'
// AFTER
'<th>' + tr('Change vs FY' + cov.priorYear) + '</th><th>' + tr('Change %') + '</th>'
```

### 4. "FY" prefix missing from regex
Existing regex `/^Share of (\d{4}) outlook held…$/` didn't match
`"Share of FY2026 outlook held by the largest customers"` because the "FY"
prefix wasn't in the pattern.

## Fixes applied

### i18n.js — Dictionary additions (15+ keys)
```
"Signal": "الإشارة"
"Change %": "نسبة التغير"
"Metric": "المؤشر"
"Actual P01-P05": "الفعلي P01-P05"
"T06 P06": "T06 P06"
"T07 P07-P12": "T07 P07-P12"
"Actual 2026 P01-P05": "فعلي 2026 P01-P05"
"2026 Outlook P01-P12": "توقعات 2026 P01-P12"
"Gross margin improvement": "تحسن هامش الربح الإجمالي"
"Gross margin compression": "انضغاط هامش الربح الإجمالي"
"Incremental operating margin": "الهامش التشغيلي الإضافي"
"Loss-making revenue exposure": "التعرض لإيرادات الخسارة"
"Top 5 customer concentration": "تركيز أكبر 5 عملاء"
"Operating leverage": "الرافعة التشغيلية"
"Product group": "مجموعة المنتج"
```

### i18n.js — Regex pattern additions (12 patterns)
```
/^FY(\d{4}) outlook margin versus FY(\d{4})\. Protect the mix…$/
/^FY(\d{4}) outlook margin versus FY(\d{4})\. Prioritize pricing…$/
/^Operating profit change divided by revenue change versus FY(\d{4})…$/
/^Share of FY(\d{4}) outlook revenue generated by product groups…$/
/^Revenue dependency on the five largest customers in the FY(\d{4})…$/
/^Revenue and profit growing in similar proportion — neutral operating…$/
/^Operating profit is growing faster than revenue — cost structure…$/
/^Revenue is growing faster than profit — costs are not scaling well…$/
/^Operating leverage cannot be calculated — one or both metrics…$/
/^Change vs FY(\d{4})$/
/^Actual (\d{4}) P01-P05$/
/^(\d{4}) Outlook P01-P12$/
/^FY(\d{4}) revenue$/
/^Share of FY(\d{4}) outlook held by the largest customers$/
```

### app.js — table header fixes
- Line 735: product movers table → wrapped all `<th>` text with `tr()`
- Line 1327: scenario bridge table → wrapped all `<th>` text with `tr()`

## Verification

- All 6 tabs scanned via Playwright `page.evaluate()` + TreeWalker
- Result: **zero English text, zero console errors**
- Syntax check: `node --check server.js app.js i18n.js` — all passed
- Smoke test: passed for non-region queries (region-filtered query has a
  pre-existing seed data issue unrelated to these changes)

## Pre-existing issue discovered

`seed_db.py --force --locale ar` changes region names to Arabic (e.g. "Africa"
→ "أفريقيا"), which breaks the smoke test's `?region=Africa` API query.
This existed before the i18n fixes and is tracked separately.
