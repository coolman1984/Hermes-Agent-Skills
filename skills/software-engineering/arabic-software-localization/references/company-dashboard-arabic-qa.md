### render.py — Arabic PDF Board Pack

**Problem:** PDF board pack rendered Arabic as `nnnn` (empty glyphs). Root causes:
1. Font not registered before cover page rendering
2. Shaped Arabic text not wrapped in `<font face="Arabic">` XML
3. Report titles not translated (English like "Yearly P&L Summary" appeared)

**Fixes applied:**
1. Added `_REPORT_AR` dictionary with translations for all 8 report titles + descriptions
2. Added `_translate_report()` helper
3. Registered font early in `render_pdf_pack()` before cover page
4. Wrapped all Arabic text in `<font face="Arabic">` tags
5. Added `force_arabic` parameter to propagate Arabic rendering to child reports

## Lesson: i18n Architecture Design

The dual-layer approach (dictionary + regex) proved effective because:
- Dictionary handles **known** strings (UI labels, fixed headings) — fast, exact match
- Regex handles **dynamic** strings (year-dependent headings, variable messages) — one pattern covers infinite variants
- The `tr()` function in app.js delegates to `I18N.translateText()` which tries dictionary first, then regex
- New translations need both: add to dictionary if static, add regex if dynamic
