# Compound — Company Intelligence Advisor OS 🧠🚀

> **الاسم:** Compound  
> **التوصيف:** نظام وكيل ذكي خاص يحوّل المعرفة المحاسبية وبيانات الشركات وأدوات البرمجة وأدلة الاستشارات إلى إجراءات تحسين حقيقية للشركات.  
> **ليس ويكيًا. ليس شات بوت.**  
> **هو مستشار مالي + تشغيلي + أتمتة قادر على تشخيص الشركات، بناء الأدوات، إنشاء لوحات القيادة، وإثبات عمله.**  
> **الحالة:** Phase 0 — مواصفات شاملة  
> **البداية:** 2026-06-17

| **Oracle / SAP** | إعادة بناء برمجيات المؤسسات حول وكلاء AI للمالية والمشتريات والموارد البشرية والإنتاج وسلسلة التوريد | المستقبل أنظمة قائمة على النتائج، ليس استخدام ERP شاشة بشاشة |

### الفجوة في السوق 🎯

المنصات الكبيرة غالية وثقيلة ومبنية للمؤسسات الضخمة.  
الفرصة الحقيقية: **نظام محلي أولاً، عملي، بمستوى استشاري للشركات الناشئة والصغيرة والمتوسطة والمصانع والشركات الفوضوية.**

معظم الشركات تريد وكلاء AI لكنها ليست جاهزة:
- Deloitte: الذكاء الوكيلي يتوسع بسرعة لكن الحوكمة متأخرة
- Gartner: 13% فقط من المؤسسات تعتقد أن لديها حوكمة وكلاء AI صحيحة

**عرض القيمة الأقوى:**

> "أنا لا أعطي الشركات وكلاء AI فقط. أعطيهم أنظمة تحسين محكومة بالذكاء الاصطناعي مع إثبات ولوحات قيادة ومنطق مالي."

## العمارة — ٨ طبقات متصلة 🏗️

### الطبقة ١: ويكي المعرفة 📚

محاسبة، مراقبة تكاليف، تخطيط مالي، رقابة داخلية، تدقيق، تسعير، تدفق نقدي، مخزون، عمليات، شركات ناشئة، ERP، وكلاء AI، أتمتة، لوحات قيادة، برمجة.

**هيكل كل بطاقة معرفة:**

| العنصر | المحتوى |
|--------|---------|
| المشكلة | وصف دقيق |
| الأعراض | كيف تكتشفها |
| البيانات المطلوبة | الملفات والأعمدة |
| طريقة التشخيص | خطوات التحليل |
| المعادلة | الصيغة الحسابية |
| الإجراءات الممكنة | قائمة الخيارات |
| المخاطر | ما قد يحدث |
| سير عمل الوكيل | تعليمات التشغيل الآلي |
| قالب المخرجات | شكل التقرير |
| حالة مثال | شركة حقيقية |

**خطة الإنتاج:** 100 بطاقة معرفة قوية كمرحلة أولى.

---

### الطبقة ٢: أنطولوجيا الأعمال 🧬

طبقة القوة الخفية — تربط كل شيء ببعضه.

**الكيانات المترابطة:**

```
حسابات ← مراكز تكلفة ← منتجات ← عملاء ← موردين
    ↓           ↓          ↓        ↓        ↓
عمليات ← KPIs ← تقارير ← ضوابط ← ملفات
    ↓           ↓          ↓
أدوات ← وكلاء ← مشكلات أعمال
```

**مثال على الترابط:**

"مشكلة مخزون" ترتبط بـ:
- تقادم المخزون
- توقعات المبيعات
- أوامر الشراء
- المخزون بطيء الحركة
- التدفق النقدي
- تكلفة المستودع
- تخطيط الإنتاج

**البحث المساند:**
- Agentic RAG + Knowledge Graph RAG يتفوقان على البحث الموجه البسيط في المعرفة المؤسسية المعقدة والاستدلال متعدد القفزات.

**خطة التنفيذ:** بناء رسم معرفي تدريجيًا — البدء بجداول SQLite خفيفة للعلاقات، والترقية لـ Neo4j عند الحاجة.

### الطبقة ٣: مكتبة الأدوات 🛠️

أدوات قابلة لإعادة الاستخدام يتحكم بها الوكيل.

**أدوات المرحلة الأولى:**

| الأداة | المدخل | المخرج |
|--------|--------|--------|
| قارئ Excel | ملف xlsx/xlsb | JSON/قاعدة بيانات |
| محول Excel-إلى-قاعدة | ملف Excel | SQLite |
| مستخرج جداول PDF | ملف PDF | CSV |
| محلل ميزان المراجعة | ملف محاسبي | تقرير شذوذ |
| محلل الموازنة مقابل الفعلي | فعلي + موازنة | تقرير انحرافات |
| محلل انحراف التكلفة | تكاليف قياسية + فعلية | تحليل الفروقات |
| محلل تقادم المخزون | حركة مخزون | تقرير أعمار |
| مدقق فواتير AP | فواتير + أوامر شراء | تقرير مخاطر |
| محلل التدفق النقدي | ميزانية + دخل | توقعات سيولة |
| محلل هوامش المبيعات | مبيعات + تكاليف | ربحية حسب المنتج/العميل |
| باني لوحات قيادة KPI | قاعدة بيانات | HTML dashboard |
| مولّد تقارير PowerPoint | تحليل | عرض تقديمي |
| باني لوحات HTML | بيانات | لوحة تفاعلية |
| مولّد حزمة الأدلة | تحليل + مصادر | مجلد إثبات |

**هيكل كل أداة:**
- المدخلات
- المخرجات
- فحوصات التحقق
- حالات الخطأ
- ملف مثال
- تعليمات الوكيل
- الإثبات المتولد

### الطبقة ٥: حزام الوكيل ⚙️

نظام التحكم — هذا هو الخندق التنافسي.

**كل مهمة وكيل يجب أن تحوي:**

| العنصر | الوصف |
|--------|-------|
| موجز المهمة | ماذا نفعل ولماذا |
| ملفات المدخلات | المسارات الدقيقة |
| الأدوات المسموحة | القائمة الحصرية |
| الإجراءات الممنوعة | الحدود الصريحة |
| المخرجات المتوقعة | الشكل والمعايير |
| قواعد التحقق | كيف نعرف أن الناتج صحيح |
| مجلد الأدلة | أين يُحفظ الإثبات |
| بوابة الموافقة البشرية | متى وأين يتدخل محمد |

**الأطر المرجعية:**
- **LangGraph:** استمرارية، سير عمل، ذاكرة، تنقيح، تحكم بشري في الحلقة

## أفضل أولى حالات الاستخدام 💰

ابدأ بحالات استخدام تمنحك فيها خلفيتك المحاسبية أفضلية غير عادلة:

| # | الاستخدام | ماذا يفعل |
|---|-----------|-----------|
| 1 | **تحسين الإقفال الشهري** | اكتشاف التأخيرات، التسويات المفقودة، العمل اليدوي، الضوابط الضعيفة |
| 2 | **تشخيص مراقبة التكاليف** | تحليل انحراف المواد، انحراف العمالة، التكاليف الإضافية، الخردة، إعادة التصنيع، خسارة الهامش |
| 3 | **مصيدة السيولة في المخزون** | كشف المخزون بطيء الحركة، الزائد، الميت، أنماط الشراء السيئة |
| 4 | **الموازنة مقابل الفعلي** | اكتشاف الإنفاق الزائد، ضعف الملكية، الانحراف المتكرر، التوفير الوهمي |
| 5 | **ربحية المنتج / العميل** | العثور على منتجات أو عملاء يبدون جيدين في الإيراد لكن ضعفاء في الهامش |
| 6 | **مخاطر AP / الفواتير** | فواتير مكررة، عدم تطابق موردين، أسعار غير طبيعية، موافقات خاطئة، مخاطر احتيال |
| 7 | **مستشار مالي للشركات الناشئة** | بناء المدرج النقدي، منطق التسعير، اقتصاديات الوحدة، لوحة مستثمر، مراقبة تكاليف |

## العمارة التقنية الموصى بها 🧱

استخدم حزمة محلية أولاً:

| الطبقة | التقنية | السبب |
|--------|---------|-------|
| **الخزنة** | مجلدات + Markdown | Obsidian-native، لا احتكار |
| **قاعدة البيانات** | SQLite ثم PostgreSQL | SQLite للبداية السريعة والمحلية |
| **التحليلات السريعة** | DuckDB | استعلامات تحليلية على ملفات مباشرة |
| **البحث الموجه** | Chroma أو Qdrant | فهرسة دلالية للملاحظات والمستندات |
| **الرسم المعرفي** | جداول SQLite خفيفة أولاً ثم Neo4j | ترقية تدريجية عند الحاجة |
| **لوحات القيادة** | HTML, CSS, JavaScript محلي | بدون خادم، تعمل في المتصفح |
| **الأتمتة** | Python scripts | أدوات CLI قابلة للتكوين |
| **مشغّل الوكيل** | Claude Code / Codex CLI / OpenCode | وكلاء خارجيون محكومون |
| **طبقة التحكم** | CLI harness (Hermes) | نظام التحكم المركزي |
| **التقارير** | Excel, PDF, PowerPoint, HTML | مكتبات Python |

**العبقرية ليست في التقنية الفاخرة. العبقرية في تصميم سير العمل.**

## خريطة البناء 🚀

## التداخل مع المشاريع القائمة

- **Company-Dashboard:** يمثل الطبقتين 3+7 جزئيًا (قاعدة بيانات + لوحات قيادة + تقارير) — يمكن أن يصبح النواة التقنية الأولى
- **Intelligence Vault:** يمثل الطبقة 1+8 (المعرفة + التعلم)
- **Hermes:** يمثل الطبقة 5 (حزام الوكيل)
- **LLM Wiki:** يمثل الطبقة 1+2 (المعرفة + الأنطولوجيا)

**الخطة:** البناء على ما هو موجود — ليس البدء من الصفر.
